# 记录鸭

分门别类记录日常频次，用格点和日历回看过往，换手机时一键把数据搬走。

一个纯前端项目：没有账号、没有服务器、没有后端，所有数据都存在你自己的手机里。

> **要把它做成手机上能装的 App？** 看 [`部署到GitHub并安装到手机.md`](部署到GitHub并安装到手机.md)，
> 从 git 初始化、推送、开启 Pages 到手机安装逐步说明，照着做约 10 分钟。

## 三种用法

### 用法一：部署成网址，手机上安装（推荐，几分钟搞定）

1. 在 GitHub 新建一个仓库，把本目录的文件全部传上去。
2. 仓库 → **Settings → Pages → Source** 选 **GitHub Actions**。
3. 推送到 `main` 分支，工作流会自动部署，得到类似
   `https://你的用户名.github.io/仓库名/` 的网址。
4. 安卓手机 Chrome 打开这个网址 → 右上角菜单 → **安装应用 / 添加到主屏幕**。

装好后有独立图标、独立窗口、可离线，和原生 App 使用感受一致。

> 嫌麻烦可以用 [Netlify Drop](https://app.netlify.com/drop)：把 `index.html`、`assets/`、`icons/`、`manifest.webmanifest`、`sw.js`
> 直接拖进网页，立刻得到一个 HTTPS 网址。

> 网址是公开的，但**数据不公开**：每个设备的数据只存在各自的浏览器里，
> 别人打开网址看到的是他自己的空界面。

### 用法二：本地预览 / 手机连同一 WiFi 试玩

```bash
node serve.js
```

启动后会打印出可用地址，例如：

```
记录鸭 已启动
  本机:   http://localhost:8080
  局域网: http://192.168.0.76:8080   (WLAN)
```

- **在电脑上试**：浏览器打开 `http://localhost:8080`。
  想看手机上的排版，按 F12 打开开发者工具，按 `Ctrl+Shift+M`
  （或点左上角的设备图标）切换设备工具栏，选 iPhone / Pixel 等机型，就是真实手机视口。
- **在真手机上试**：手机连上同一个 WiFi，浏览器打开
  `http://192.168.0.76:8080`（换成你打印出来的那个 IP）。
  功能和界面都能完整试，**但这一步不能「安装到主屏幕」**——
  浏览器只在 HTTPS 或 localhost 下允许安装，局域网 HTTP 不行。
  想真实安装请走用法一或用法三。

> 手机打不开时，多半是 Windows 防火墙拦了：
> 控制面板 → Windows Defender 防火墙 → 允许应用通过防火墙 →
> 找到 Node.js，把「专用网络」勾上（或临时关掉防火墙验证）。

> 注意：手机和电脑访问的是**两个独立的本地数据库**，数据不互通。
> 要在两边同步，用设置页的同步码或备份文件。

### 用法三：编译成真正的 APK

本机不需要装 Android Studio，让 GitHub Actions 帮你编译：

1. 把项目推到 GitHub（同上）。
2. 仓库 → **Actions → 构建安卓 APK → Run workflow** → 选 `debug` → 运行。
3. 大约 5–10 分钟后，在工作流详情页底部下载 `jiluya-apk-debug` 里的 `app-debug.apk`。
4. 传到手机安装（Android 会提示"未知来源"，允许即可）。

如果想在本机编译，需要先装 Android SDK 和 JDK 17，然后：

```bash
npm install
npm run cap:init      # 生成 android/ 工程
npm run cap:sync
npm run cap:patch     # 注入摄像头权限
cd android && ./gradlew assembleDebug
```

APK 中的包名是 `app.jiluya.recorder`，想改就编辑 `capacitor.config.json` 里的 `appId`。

## 换手机时怎么搬数据

**途径 A：同步码（记录不多时最快）**

- 旧手机：设置 → 生成同步码（二维码）
- 新手机：设置 → 扫描二维码导入，对准即可
- 数据量大到二维码装不下时，用「复制 / 分享」把同步码文本发到微信，新手机粘贴导入
- 同步码默认**不含图片**（图片体积大），要连图片一起搬就勾选「包含图片」，或改用途径 B

**途径 B：备份文件（什么都带走）**

- 旧手机：设置 → 导出备份文件 → 通过微信/蓝牙/网盘发到新手机
- 新手机：设置 → 从备份文件导入 → 选择合并（推荐）或覆盖

导入时选**合并**最安全：同 ID 的记录保留较新的那份，新旧数据能拼到一起。

```

manifest.webmanifest       PWA 清单（图标、名称、独立窗口）
sw.js                      Service Worker，负责离线缓存
serve.js                   本地预览服务器
capacitor.config.json      APK 打包配置
assets/css/style.css       全部样式
assets/js/store.js         数据层：存储、统计、导入导出、同步码
assets/js/app.js           界面与交互
assets/js/sync.js          设置页、备份、扫码
assets/js/icons.js         内置 SVG 图标（无外部依赖）
assets/vendor/qrcode.js    二维码生成库（本地副本，离线可用）
icons/                     App 图标
scripts/                   打包脚本
tests/                     冒烟测试：数据层 58 项 + 界面 108 项 + 真实浏览器 13+15+15 项
.github/workflows/         自动部署 Pages / 自动构建 APK
```

## 常见问题

**Q：换手机后数据会丢吗？**
A：不会自动丢，但也不会自动跟过来——数据只在本机。换机前记得用同步码或备份文件搬一次。

**Q：删掉一个子项目，它下面的记录会没吗？**
A：不会消失。这些记录会自动归为「未分类」，仍算在项目的总统计里。

**Q：为什么改完代码刷新后还是老样子？**
A：Service Worker 现在是「网络优先」，正常刷新就能拿到新版；实在不生效就清除该站点的数据重新打开（记得先导出备份）。

**Q：清缓存会不会把记录清掉？**
A：Chrome 里清除「网站数据」会一并清掉本地记录，请先导出备份。装成 App 后正常清理内存不会被清。

**Q：扫码用不了？**
A：扫码依赖浏览器的摄像头条码识别能力，部分浏览器没有。改用粘贴同步码文本，效果一样。

**Q：能存多少图片？**
A：浏览器给单个站点的本地存储上限通常是 5MB 左右，图片会压缩到长边 720px 后保存。
设置页有容量进度条，接近上限时导一份备份再清理旧图。

**Q：几个人能共用同一个网址各自记录吗？**
A：能，各记各的，数据互不干扰（都在各自手机上）。

## 想改代码的话

没有构建步骤，改完刷新页面就生效。全部逻辑在 `assets/js/` 下三个文件里，
`store.js` 管数据，`app.js` 管界面。想加功能（比如提醒、图表、标签）
直接在 `store.js` 里扩数据字段，`app.js` 里加渲染即可。

改完可以跑一遍回归测试（157 项，免浏览器）：

```bash
npm install        # 仅首次，装 jsdom
npm test
```

jsdom 只能验逻辑，看不见样式。想连视觉效果一起验，可以跑真实浏览器测试
（调用本机已装的 Chrome，不需要下载浏览器内核）：

```bash
npm install                 # 额外装 playwright-core
node serve.js               # 另开一个终端，服务要跑着
npm run test:browser
```

它会用手机视口真的去点按钮、填表单，顺带截图，最后打印通过项。
**注意：该测试会清空 `localhost:8080` 上的本地数据**（先写测试数据），别在存了真实记录的浏览器里跑。
